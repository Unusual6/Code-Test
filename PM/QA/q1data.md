# AI平台/Agent 产品经理数据分析高频问答（精选）

> 聚焦稳定性、效果、成本、转化四大核心维度，适合面试与日常复盘

---

### 1. 指标上涨/下跌，怎么判断是正常波动还是真实问题？

**答**：  
先看同期基线（昨日、上周同日），判断波动幅度；结合标准差看是否属于统计噪音；同时排查是否有告警、埋点异常、版本发布、模型切换。  

- 幅度小 + 无版本变更 + 无集中报错 → 大概率是正常波动  
- 大幅偏移 + 刚好发版/扩容/模型切换 → 判定为真实问题

---

### 2. 任务失败，怎么区分是工程稳定性、功能bug，还是AI效果问题？

**答**：  
通过埋点日志和 trace_id 链路区分：

- 有报错码、超时、连接失败 → **工程稳定性问题**
- 流程执行逻辑不符合设计 → **功能 bug**
- 链路跑通、无报错，但输出错误、幻觉、工具参数写错 → **AI 效果问题**

---

### 3. 漏斗转化率下降，怎么找到核心卡点？

**答**：  
1. 逐层对比前后版本漏斗转化率  
2. 找到流失率明显上升的层级  
3. 对该层级做下钻（用户、模型、工具、query 类型）  
4. 定位是这一步的能力短板

---

### 4. 算力成本上涨，怎么判断是调用量增加，还是单请求 token 变高？

**答**：  
拆分公式：**总 token = 请求量 × 平均单请求 token**

- 请求量上涨 → 用量增长  
- 单请求 token 上涨 → 通常是 prompt 变长、召回文档变多、模型输出变长

分别看两个因子的趋势，就能快速定位原因。

---

### 5. 新版本上线，怎么验证优化有没有效果？要不要关注负向指标？

**答**：  
用 A/B 或灰度分组，对比实验组与对照组的核心目标指标。  

**必须同时盯负向副作用指标**（token 消耗、时延、安全拦截率等）。  
即使核心指标提升，如果副作用明显变差，也属于不合格的迭代。

---

### 6. 大量 badcase，怎么快速找到共性？

**答**：  
抽样提取失败的 query、召回内容、模型输出、工具调用记录，进行归类，看是否集中在以下几类：

- 领域知识缺失
- 参数格式错误
- 歧义提问
- RAG 召回质量差
- 模型本身能力边界问题

---

### 7. 新老用户任务成功率差异大，一般怎么分析？

**答**：  
新用户大概率不熟悉平台用法、prompt 写得差、不会编排 Agent；老用户已经形成使用范式。  

优先排查：
- 新用户是否集中在复杂场景
- 新手引导、示例模板、推荐 prompt 是否不足

---

### 8. 多个优化方向都能改善指标，怎么判断优先做哪一个（ROI最高）？

**答**：  
从两个维度评估：

1. **问题影响量级**（受影响的任务数/用户数、损失成本）
2. **开发成本与风险**

优先选择「影响面大、投入小、风险低」的方案。

---

### 精简口述版（面试快速回答）

1. **波动 vs 真实问题**：对比同期基线 + 排查发版/埋点/告警。小幅无变更是波动，大幅+变更是真实问题。  
2. **工程 vs AI效果**：看 trace 和错误码。超时/报错是工程，链路正常但结果错是AI效果。  
3. **漏斗卡点**：逐层对比转化率，定位流失突增层级再下钻。  
4. **成本上涨**：拆成「请求量 × 单请求token」，分别看趋势。  
5. **版本效果验证**：核心指标 + 负向副作用指标必须同时看。  
6. **badcase共性**：抽样归类 query、召回、工具调用、模型能力边界。  
7. **新老用户差异**：新用户多是使用问题，优先看引导和模板。  
8. **优先级判断**：影响量大 + 投入小 + 风险低，优先做。
