# 产品经理必备概念术语手册

> 本手册按工作场景分类整理产品经理日常必须掌握的核心概念与术语，适合新人快速入门，也适合老手随时查阅。

---

## 一、产品策略与规划

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **产品愿景** | Product Vision | 产品长期要达成的理想状态，是团队共同努力的方向灯塔 |
| **产品战略** | Product Strategy | 连接愿景与执行的路径规划，回答“为谁解决什么问题、如何赢” |
| **产品路线图** | Product Roadmap | 展示产品未来发展方向与优先级的可视化计划（常见 Now-Next-Later 格式） |
| **产品生命周期** | Product Life Cycle (PLC) | 产品从导入→成长→成熟→衰退的完整过程，不同阶段策略不同 |
| **价值主张** | Value Proposition | 产品能给用户带来的核心价值与差异化承诺 |
| **产品市场匹配** | Product-Market Fit (PMF) | 产品真正解决了一群人的核心需求，并被市场认可的状态 |
| **最小可行产品** | Minimum Viable Product (MVP) | 用最少资源验证核心假设的最小功能版本 |
| **最小可销售产品** | Minimum Marketable Product (MMP) | 具备足够功能、可以正式推向市场销售的版本 |
| **护城河** | Moat | 产品或企业形成的可持续竞争壁垒 |
| **SWOT 分析** | SWOT Analysis | 优势（Strengths）、劣势（Weaknesses）、机会（Opportunities）、威胁（Threats）分析框架 |
| **波特五力模型** | Porter's Five Forces | 分析行业竞争强度的经典模型（供应商、买家、新进入者、替代品、现有竞争者） |
| **Go-to-Market 策略** | GTM Strategy | 产品如何进入市场、触达用户并实现商业目标的整体计划 |

## 二、需求与用户研究

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **用户画像** | User Persona | 基于真实数据抽象出的典型用户模型，帮助团队共情用户 |
| **用户旅程** | User Journey | 用户完成某个目标的完整路径，包含触点、情绪与痛点 |
| **痛点 / 痒点** | Pain Point / Gain Point | 痛点是必须解决的问题；痒点是解决后会更爽的需求 |
| **Jobs to be Done (JTBD)** | Jobs to be Done | 用户“雇佣”产品来完成的真实任务与目标 |
| **需求池** | Requirement Pool / Backlog | 所有待处理需求的集合，需持续维护优先级与状态 |
| **用户故事** | User Story | 以用户视角描述需求的格式：“作为…，我想要…，以便…” |
| **史诗** | Epic | 较大的用户故事或功能模块，通常需要拆分为多个小故事 |
| **验收标准** | Acceptance Criteria | 判断需求是否完成的明确条件（Definition of Done 的一部分） |
| **优先级排序** | Prioritization | 对需求进行价值与成本权衡排序的过程 |
| **RICE 模型** | RICE | Reach（覆盖）、Impact（影响）、Confidence（信心）、Effort（工作量）优先级框架 |
| **MoSCoW 方法** | MoSCoW | Must / Should / Could / Won't 需求优先级分类法 |
| **竞品分析** | Competitive Analysis | 系统研究竞争对手产品，找出差异与机会 |
| **需求分析** | Requirement Analysis | 将用户需求转化为可落地的产品功能的过程 |

## 三、敏捷与开发管理

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **敏捷开发** | Agile | 强调快速迭代、拥抱变化、以用户价值为中心的开发方法论 |
| **Scrum** | Scrum | 最流行的敏捷框架，包含角色、事件与工件 |
| **产品负责人** | Product Owner (PO) | 负责产品待办列表（Backlog）优先级与价值最大化的角色 |
| **Scrum Master** | Scrum Master | 服务型领导，帮助团队移除障碍、践行 Scrum |
| **冲刺** | Sprint | 固定时长（通常 1-2 周）的迭代开发周期 |
| **产品待办列表** | Product Backlog | 所有待开发需求的优先级排序清单 |
| **冲刺待办列表** | Sprint Backlog | 当前 Sprint 承诺完成的工作项 |
| **每日站会** | Daily Standup | 每天简短同步进度、障碍与计划的会议 |
| **迭代回顾** | Retrospective | Sprint 结束后复盘做得好与需改进之处的会议 |
| **迭代评审** | Sprint Review | 向干系人展示已完成工作、收集反馈的会议 |
| **看板** | Kanban | 可视化工作流、限制在制品（WIP）的敏捷方法 |
| **技术债** | Technical Debt | 为快速上线而采用的临时方案，后续需要偿还的成本 |
| **Definition of Done (DoD)** | Definition of Done | 团队共同约定的“完成”标准 |
| **故事点** | Story Point | 相对估算工作量的单位（而非人天） |

## 四、文档与设计

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **商业需求文档** | Business Requirements Document (BRD) | 从商业视角阐述产品背景、目标、价值与成功标准 |
| **市场需求文档** | Market Requirements Document (MRD) | 分析市场、用户、竞争与机会，指导产品方向 |
| **产品需求文档** | Product Requirements Document (PRD) | 详细描述功能、逻辑、规则、异常与验收标准的核心文档 |
| **原型** | Prototype | 可交互的产品模拟界面，用于验证交互与流程 |
| **线框图** | Wireframe | 黑白低保真结构图，专注布局与信息架构 |
| **信息架构** | Information Architecture (IA) | 产品内容与功能的组织、分类与导航结构 |
| **UI / UX** | User Interface / User Experience | 界面设计 vs 用户体验设计 |
| **设计系统** | Design System | 统一的颜色、字体、组件与规范，保证产品一致性 |
| **空状态** | Empty State | 页面无数据时的引导与占位设计 |
| **交互设计** | Interaction Design | 定义用户与产品之间如何互动的设计 |

## 五、数据与指标

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **北极星指标** | North Star Metric | 最能代表产品核心价值的单一关键指标 |
| **关键绩效指标** | Key Performance Indicator (KPI) | 衡量目标达成情况的量化指标 |
| **OKR** | Objectives and Key Results | 目标与关键结果框架：目标定性，关键结果可量化 |
| **DAU / MAU** | Daily / Monthly Active Users | 日活跃用户 / 月活跃用户 |
| **留存率** | Retention Rate | 用户在一段时间后仍继续使用产品的比例（次留、7留、30留） |
| **流失率** | Churn Rate | 用户停止使用产品的比例 |
| **转化率** | Conversion Rate | 完成目标行为的用户占比 |
| **漏斗** | Funnel | 用户从入口到最终转化的各阶段转化路径可视化 |
| **LTV / CAC** | Lifetime Value / Customer Acquisition Cost | 用户终身价值 / 获客成本，健康产品 LTV > CAC |
| **GMV** | Gross Merchandise Volume | 成交总额（注意不等于收入） |
| **PV / UV** | Page View / Unique Visitor | 页面浏览量 / 独立访客数 |
| **A/B 测试** | A/B Testing | 将用户随机分组，对比不同版本效果的实验方法 |
| **灰度发布** | Canary Release / Gradual Rollout | 新功能先向小部分用户开放，验证后再全量 |
| **埋点** | Event Tracking | 在产品中记录用户行为数据的技术手段 |
| **ROI** | Return on Investment | 投资回报率 |

## 六、增长与运营

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **AARRR 模型** | Acquisition, Activation, Retention, Revenue, Referral | 海盗指标：获取→激活→留存→收入→推荐 |
| **增长黑客** | Growth Hacking | 用低成本、数据驱动的方式快速实现用户增长 |
| **病毒系数** | Viral Coefficient (K-factor) | 每个用户平均带来的新用户数量 |
| **激活** | Activation | 用户完成关键行为、真正体验到产品价值的时刻（Aha Moment） |
| **用户分层** | User Segmentation | 按行为、价值、生命周期等对用户进行分组运营 |
| **千人千面** | Personalized Experience | 根据用户特征与行为展示不同内容与功能 |
| **推送** | Push Notification | 主动触达用户的消息通知 |
| **LBS** | Location Based Service | 基于地理位置的服务 |

## 七、商业模式与行业常见术语

| 术语 | 英文全称 / 缩写 | 解释 |
|------|----------------|------|
| **B2B / B2C / C2C** | Business-to-Business / Business-to-Consumer / Consumer-to-Consumer | 企业对企业 / 企业对消费者 / 消费者对消费者 |
| **SaaS** | Software as a Service | 软件即服务，按订阅收费的软件模式 |
| **SPU / SKU** | Standard Product Unit / Stock Keeping Unit | 标准化产品单元 / 库存量单位 |
| **GMV vs 收入** | GMV vs Revenue | GMV 是成交总额，收入是扣除成本、佣金后的实际收入 |
| **MRR / ARR** | Monthly / Annual Recurring Revenue | 月经常性收入 / 年经常性收入 |
| **订阅制** | Subscription Model | 用户按周期付费使用服务的商业模式 |
| **抽佣** | Commission / Take Rate | 平台从交易中抽取一定比例作为收入 |

## 八、团队协作与其他重要概念

| 术语 | 解释 |
|------|------|
| **干系人 / 利益相关者** | Stakeholder，受产品影响或能影响产品的个人与组织 |
| **跨职能团队** | Cross-functional Team，包含产品、设计、研发、运营等不同角色的团队 |
| **里程碑** | Milestone，项目关键节点与阶段性成果 |
| **排期** | Scheduling，将需求按优先级安排到具体时间周期 |
| **颗粒度** | Granularity，需求或任务拆分的细致程度 |
| **可行性分析** | Feasibility Analysis，从技术、商业、资源等角度评估项目是否可做 |
| **技术可行性** | Technical Feasibility，评估技术实现难度与风险 |
| **业务可行性** | Business Feasibility，评估是否有商业价值与市场空间 |

## 快速记忆口诀（新人友好）

1. **先想清楚再动手**：愿景 → 战略 → 路线图 → MVP
2. **用户永远第一**：画像 → 旅程 → 痛点 → 用户故事
3. **数据说话**：北极星 → KPI → 漏斗 → A/B 测试
4. **敏捷落地**：Backlog → Sprint → Review → Retrospective
5. **增长闭环**：AARRR 模型贯穿始终
