## 1. 背景与目标

### 1.1 项目背景
在科学计算与实验自动化场景中，科研人员面临以下痛点：
- 复杂实验流程配置繁琐，跨系统操作成本高
- 执行过程不透明，出问题难以定位
- 参数优化严重依赖人工经验，效率低且不稳定
- 传统固定工作流难以覆盖多样化、非标准化需求

本平台基于大模型 Agent 能力，通过自然语言理解任务目标，自动进行任务拆解、工具/设备调用、执行控制与结果反馈，并支持关键节点人工确认与智能参数优化，实现从“需求描述”到“结果交付”的端到端闭环。

### 1.2 产品目标
**短期目标（商业化初期）**：
- 支撑已有试点机构稳定使用，并实现付费转化
- 打磨 2-3 个高频标准化场景，形成可复制标杆
- 任务成功率稳定在 95% 以上，关键路径可控、可观测

**中期目标**：
- 具备多租户与基础平台能力
- 支持更多机构快速接入
- 核心能力可抽象复用到相邻场景

### 1.3 成功指标（北向指标）

| 指标类型 | 指标名称 | 目标值 | 说明 |
|----------|----------|--------|------|
| 核心效果 | 任务成功率 | ≥95% | 从请求到最终结果符合预期 |
| 体验 | 人工接管率 | 监控并持续优化 | 关键节点确认后的实际干预比例 |
| 效率 | 平均任务完成时长 | 对比基线下降 | 含等待确认时间 |
| 商业 | 付费转化与复用率 | 持续提升 | 试点转付费、月活跃任务量 |
| 质量 | 工具调用准确率 | ≥90% | 正确选择并成功调用工具/设备 |

## 2. 用户与场景

### 2.1 目标用户
- 主要用户：科研人员、实验操作人员
- 次要用户：实验室管理员、机构技术对接人
- 使用环境：实验室 / 办公环境，需对接真实设备与计算资源

### 2.2 核心使用场景
1. **自然语言发起复杂实验任务**  
   用户用自然语言描述目标，Agent 自动拆解并执行。

2. **基于已有标准工作流执行**  
   选择或复用已固化的标准化流程，降低不确定性。

3. **带智能参数优化的实验**  
   在具备历史数据的前提下，开启贝叶斯优化 Skill，自动寻优。

4. **执行过程监控与人工干预**  
   查看进度、状态、中间结果，在关键节点进行确认或中断。

## 3. 产品范围与边界

### 3.1 本期做（In Scope）
- 自然语言任务理解与多步骤拆解
- 基于 LangGraph 的工作流编排
- RAG 知识检索
- MCP Server / API / Python 函数 / MQTT 设备对接
- 关键人工确认节点（高成本、不可逆动作）
- 执行状态回传与对话界面展示
- 贝叶斯优化 Skill（可选）
- 基础任务日志与结果交付

### 3.2 本期不做（Out of Scope）
- 完全无人工干预的全自动高风险操作
- 多 Agent 复杂协作（本阶段以单 Agent 为主）
- 完整的多租户计费与权限体系（放在下一阶段）
- 通用跨行业大规模扩展

### 3.3 功能边界原则
- 只开放已校准、可观测、可回滚的 Skill 与工具
- 涉及真实设备动作、高成本计算资源的操作，必须人工确认
- 低成本生成类、可重跑的计算任务可自动执行
- 通过黑名单 / Harness 限制危险动作

## 4. 整体方案

### 4.1 核心架构思路
采用「Agent 自主决策 + 人工兜底 + 标准工作流固化」的混合架构：
- 自然语言路径：灵活应对新需求与探索性任务
- 已有流程路径：高频标准任务直接复用，降低风险与成本
- 关键节点人工确认：保证安全与可控
- 执行过程可观测：进度、状态、参数、结果实时反馈

### 4.2 关键用户流程（简化）

1. 用户输入任务目标（自然语言 or 选择已有流程）
2. Agent 进行意图理解与任务拆解
3. 生成执行计划，展示给用户确认（如需要）
4. 按节点执行，遇到高风险动作暂停等待确认
5. 工具/设备调用，状态实时回传
6. 可选：触发贝叶斯优化循环
7. 汇总结果并返回用户，支持追问与补充

## 5. 功能需求详述

### 5.1 任务理解与拆解
- 支持自然语言描述任务目标
- 自动进行需求澄清（信息不足时追问）
- 输出结构化任务步骤与依赖关系
- 支持与已有标准工作流匹配

### 5.2 工作流编排与执行
- 基于 LangGraph 实现有状态编排
- 支持顺序、分支、循环等基础控制流
- 每个节点记录输入、输出、状态、耗时
- 支持执行中断与恢复

### 5.3 工具与设备集成
- 支持 MCP Server、API、Python 函数、MQTT 设备网关
- 工具调用前进行参数校验
- 限制重复调用（次数 + 入参去重）
- 调用失败有明确错误码与重试/降级策略

### 5.4 人工确认与风险控制
- 高成本 / 不可逆动作强制进入确认节点
- 确认界面展示：拟执行动作、预估成本/风险、上下文摘要
- 支持「确认执行」「修改参数」「拒绝/中断」
- 支持后续对低频低风险模板进行信任授权（规划中）

### 5.5 智能优化（贝叶斯优化 Skill）
- 以可选 Skill 形式提供
- 前提：存在可优化参数 + 一定历史数据
- 支持全自动 / 半自动（每轮展示结果供用户决策）模式
- 优化过程可视化（参数轨迹、指标变化）
- 最终结果对比经验基线，并给出简要解释

### 5.6 结果反馈与可观测
- 对话界面实时展示执行进度与关键状态
- 支持查看中间结果、日志、工具调用详情
- 最终结果结构化输出，支持导出
- 失败时提供归因信息与建议动作

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 常规任务首响 < 3s，工具调用超时可配置 |
| 可靠性 | 关键状态可恢复，支持断点续跑 |
| 安全性 | 动作黑名单、权限校验、操作审计日志 |
| 可观测性 | 全链路日志、关键指标监控、失败告警 |
| 扩展性 | 新工具 / 新设备以配置或低代码方式接入 |

---

## 7. 数据与埋点要求

必须埋点的核心事件：
- 任务创建 / 意图理解结果
- 任务拆解完成
- 人工确认曝光与操作（确认/修改/拒绝）
- 工具调用（成功/失败/重试）
- 优化 Skill 触发与轮次结果
- 任务最终成功 / 失败及失败原因分类
- 用户追问与补充行为

---

## 8. 验收标准（核心）

1. 标准测试集任务成功率 ≥ 95%
2. 高风险动作 100% 进入人工确认，无漏放
3. 工具重复调用被有效拦截
4. 执行过程关键状态可在对话界面实时查看
5. 贝叶斯优化在具备数据的前提下可正常触发并产出对比结果
6. 主要失败 case 可被分类归因

---

## 9. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 长链路任务上下文丢失 | 拆解错误、成功率下降 | 上下文管理优化 + 分阶段确认 |
| 设备状态回传延迟/丢失 | 后续节点基于错误状态执行 | 回调 + 超时重试 + 最终确认 |
| 用户对黑盒不信任 | 转化与复用受阻 | 强化可观测与解释性 |
| 商业化转化不及预期 | 影响后续投入 | 聚焦标杆场景，快速验证付费 |
